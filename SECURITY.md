# Security model

Read-only is the default. Optional writes/capture require explicit deployment opt-in and exact action confirmation. Normal use is MCP preview → host confirmation → MCP apply, with SSH internal. See [write safety](docs/writes.md) and [host trust](docs/approvals.md).

- Typed tools accept bounded identifiers/settings, not shell commands, arbitrary files, Redis keys, flags or executable source. Configured boxes use literal IPs and dedicated identities. TCP probes have configured destination scopes.
- OpenSSH ignores user configuration, disables interactive/password/agent/forwarding paths and requires strict host-key verification against persistent known_hosts.
- Reviewed forced-command gates pin helper bytes and supported operations. Router helpers/import registries are installed only through separately approved administration. `pi` is powerful; application flags alone do not constrain an unrestricted stolen key.
- HTTP uses a file-backed dedicated bearer, Host checks and Origin rejection, bounded bodies, no query tokens and no access logging. Keep backend reachability private. The gateway authenticates and authorizes users; it uses a separate bearer credential for this backend. Preserve existing identities on upgrades.
- Host-confirmed mode trusts the authenticated host to ask the human. The server does not attest chat consent, and an authorized malicious client can violate that UX policy. Exact plans, state/target/settings binding, expiry, firmware/operation restrictions and durable consumption prevent different/replayed operations, not malicious-host intent.
- File-based approval and its issuer are removed. Old configurations fail closed and require explicit host-confirmed migration; preserve the durable execution ledger.
- Router reads project allowlisted fields before transport. Saved-profile parsing may encounter secret material in router memory but returns only permitted metadata. Import credentials stay router-local. Do not query credential-bearing full init/profile APIs or log raw management responses.
- Private rule descriptions, addresses, names, memberships and flow metadata reach the authorized client. Minimize retention; never publish live data. Remote strings remain untrusted data, not instructions. Projection cannot prevent a malicious appliance encoding secrets in permitted metadata fields.
- Capture is bounded to15seconds/100packets and one target/interface. Packet prefixes may enter router memory; only parsed tuples/flags/lengths/times leave it. No PCAP/payload export or files. Cancellation/timeouts have cleanup backstops; network failure cannot guarantee immediate cleanup. See [capture limits](docs/traffic-capture.md).
- Persistent management uses existing native routes, never enabling development APIs or directly changing policy Redis fields. Asynchronous acknowledgment/stored state is not proof of enforcement. Snapshots are not atomic against concurrent writers. Imports/forwards require disclosed maintenance windows; uncertain outcomes require inspection, not blind retry/rollback.
- Kernel route/filter/DNAT tools are temporary and table/chain scoped. General permanent routes, arbitrary rule CRUD, global mutations, RADIUS enrollment, unrestricted shell, package/service administration and cross-plugin execution remain unsupported.
- Keep config/key mounts read-only; private audit/consumption storage persistent and UID-restricted. Do not erase the ledger during upgrade. Container image rollback does not undo router state. Review hash/operation changes before updating a forced-command gate.

Report vulnerabilities privately through the repository owner's GitHub contact. Never include credentials, actual network identifiers, raw traffic or real VPN files in public issues or fixtures.
