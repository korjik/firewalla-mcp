# Troubleshooting

- **Startup exits:** validate `config.json` and its absolute file paths. Unknown fields, invalid IPs/ports, and malformed labels fail startup. `FIREWALLA_MCP_CONFIG` must name a readable file. stdout is reserved for MCP; inspect stderr locally, without posting secrets.
- **Host-key verification or SSH failure:** reproduce with the dedicated key and `StrictHostKeyChecking=yes` from the actual MCP host. Verify address, port, known-hosts entry, file ownership, and independent fingerprint. Do not bypass verification. In Docker verify the container UID can read mounted files and the key is not group/world readable.
- **Password or passphrase prompt:** the server is deliberately noninteractive. Provision an appropriate dedicated key as described in setup; it does not use SSH agents.
- **Utility or permission unsupported:** run `capabilities`. The remote Python helper requires Python 3, timeout and each adapter's utility. Some diagnostics require existing passwordless `sudo -n`. The project does not install packages or change sudo policy. Use a less privileged supported query instead.
- **Large firewall table unsupported:** the 128 KiB remote command cap applies before parsing. This is safer than interpreting an incomplete table. A future filtered adapter can address larger tables; do not globally remove bounds.
- **No devices:** `device_lookup` requires a known MAC. Use `device_inventory` and follow its cursor; SCAN may return duplicates or empty pages before completion. A stale/nonstandard Redis record returns unsupported.
- **VPN looks UP but application fails:** interface state does not resolve device policy, verify provider assignment, prove return routing, or prove application binding. Those are separate evidence in the diagnosis.
- **Public-port timeout:** it is inconclusive. Test from an operator-verified independent network. No UDP verdict can be derived from the TCP tool, and local hairpin failures are not proof of global closure.
- **Docker appears idle:** stdio is waiting for a client. Use a JSON-RPC MCP initialize/list-tools roundtrip; stdio has no HTTP health URL; optional HTTP exposes authenticated /healthz. Run with `-i` (or Compose `-T` with stdin open), not a TTY that might alter JSON-RPC framing.
- **Docker build behind a corporate proxy:** preserve Docker proxy configuration and trusted CA verification. The Dockerfile supports an optional BuildKit `proxy_ca` secret for pip: `docker build --secret id=proxy_ca,src=/path/to/trusted-ca-bundle.pem -t firewalla-mcp:local .`. Never disable TLS verification. This build secret is not saved into image layers.
- **Expected write tools missing:** inspect the actual `tools/list` and `write_capabilities` response. Select one catalog flag and explicitly enable its configuration; default startup is read-only. A tool's presence is not proof that a firmware contract or router gate permits it.
- **File-approval configuration rejected:** follow [migration](approvals.md#migrating-from-file-based-approval). Remove obsolete issuer/inbox fields, explicitly accept host-confirmed mode and preserve the private audit/consumption mounts. Do not delete replay records to make a retry work.
- **Helper hash mismatch or unsupported firmware:** compare the installed artifact and source contract with the selected release. Review the exact change and update matching pins only through authorized administration. Never disable verification, spoof the revision or enable development endpoints.
- **Expired or lost plan:** restart discards pending plans. Obtain a fresh preview and confirmation; do not recreate an old plan ID or alter its expiry.
- **Partial/uncertain result:** inspect current state before another action. `partial_expired` after managed-rule creation means a verified new disabled rule was left in place and no activation/cleanup was sent. Do not blindly reapply or remove state another actor may have changed.
- **Gateway shows old parameters:** compare direct backend and gateway `tools/list`, refresh discovery and tool associations, then refresh the client's tools. Preserve the integration/OAuth identity; do not recreate it just to refresh schemas.
- **HTTP 401/403:** check the gateway's dedicated backend bearer, exact allowed Host and private network path. The backend rejects browser Origin headers and does not validate end-user OAuth tokens. Follow [authentication](authentication.md); do not use query tokens or turn off checks.
